# QA report: main @ 65d362d (2026-10-18)

Tester: Gil (QA). Scope: public (signed-out) site, all routes, desktop + 375px, light + dark.

## Environment
- Build: `main` at `65d362d` (merge of dev/noa/manual-verification). `node --check site/app.js` OK; `node tests/smoke.test.js` 7/7 pass.
- Data: `tests/fixtures/data.json` copied to `site/data.json` (99 athletes, 33 sports, 83 competitions, 8 changes).
- Browser: headless Google Chrome driven over CDP (scratch script). The built-in Browser pane refused to open
  `http://localhost:8765` ("navigation denied or failed"), so it could not be used.
- Server: `python3 -m http.server` first, then a variant that sends `charset=utf-8`. Plain `http.server` sends

- Viewports: 1280x900 and 375x812 (CSS px), with `prefers-color-scheme` emulated as light and dark.
- Not covered: editor mode (`#admin`, live DB, review queue). Those need a signed-in editor in the artifact host.

## Issues

### P0: blockers
None. Every route renders, there are no JS errors in the console (only a local `favicon.ico` 404), and there is no horizontal page scroll at 375px with real data.

### P1
**P1-1. Mobile nav hides 3 of 5 sections, including the current one.** Route: all, at 375px.
Steps: open `#calendar` at 375px. Expected: every section is reachable and visible, and the current page's tab is fully visible.
Actual: `.links` scrolls horizontally with no visual cue. "לוח תחרויות", "עדכונים" and "אודות" are clipped or off-screen, and on `#calendar` the active tab reads "לוח תחרויו".
Fix: wrap the links onto a second row under 640px (`.links{flex-wrap:wrap}`), or add a fade or scroll cue and call `scrollIntoView({inline:"nearest"})` on the `aria-current` link after each route.

**P1-2. Long unbroken strings push panels off-screen to the left, and the clipped text cannot be reached.** Routes: `#a-*`, `#sport-*`, `#home`, `#calendar`.
Steps: give an athlete a long URL in `notes`, or a long name, rank or event, then open the athlete page at 375px. Expected: the text wraps inside the panel. Actual: the panel grows wider than the viewport. In RTL the overflow goes to the left, where the page cannot scroll, so the content is cut off (`scrollWidth` stays 375). The stage track was measured at left=-1412px.
Cause: `.panel` and `main` are grid containers with an implicit `auto` column, so one child that cannot wrap widens the whole column. Also, `.card .nm`, `.card .ev` and the athlete `notes <p>` have no `overflow-wrap`. Today's fixture has no token longer than 21 characters, but URLs pasted into `notes` by editors or by the job will trigger this.
Fix: `main,.panel{grid-template-columns:minmax(0,1fr)}`, `.card,.panel p{overflow-wrap:anywhere}`.

**P1-3. Home "מה התעדכן" panel spreads its rows across the full height of the neighbouring panel.** Route: `#home`, desktop (any width where `.grid2` has two columns).
Expected: the change rows stack at the top. Actual: there are 130–155px gaps between rows and large empty space, because the panel is stretched to match the long "14 הימים הקרובים" list next to it. The rows measured 39/62px with the fix and 132/155px without it.
Fix: `.panel{align-content:start}` (verified in the browser).

**P1-4. Calendar filters throw keyboard focus back to `<body>`.** Route: `#calendar`.
Steps: Tab to "רק תחרויות העפלה" and press Space, or change the sport select. Expected: focus stays on the control. Actual: `route()` re-renders the whole view, so focus goes to `BODY` and the keyboard or screen-reader user has to Tab from the top of the page again. This happens after every filter change.
Fix: in the `input` handler, call `refresh()`-style logic that restores focus to the element with the same id. Better still, re-render only the list below the toolbar.

**P1-5. Search ignores apostrophe and geresh variants.** Route: `#home`.
Steps: search `ג'ודו` (apostrophe, which is what most keyboards type). Expected: judo and its 9 athletes. Actual: "נמצאו 0". `ג׳ודו` (geresh) works.
The reverse is also true: the data itself uses `'` in 63 strings (for example `קוזמיצ'וב` and `200 מ' גב`), so a user typing `׳` misses those.
Fix: normalize both the query and the haystack, for example `s.replace(/[׳'`’]/g, "'").replace(/[״"]/g, '"')`, before matching. The data inconsistency with CLAUDE.md's "geresh ׳ not apostrophe" rule is noted separately under P2-8.

**P1-6. No skip link.** Route: all.
Expected: the first Tab reaches a "דילוג לתוכן" link that targets `#view`. Actual: the first Tab goes to the brand link, then 5 nav links, before reaching content. This was also the case on a deep link to `#a-raz-hershko`.
Note: in-page `href="#view"` would trigger the hash router. Use a button, or a link with a click handler that runs `preventDefault()` and focuses `main` (`tabindex="-1"`).

### P2
1. **The not-found view has no `<h1>`.** Routes: `#nope`, `#a-nobody`, `#sport-nope`, and `#admin` for public visitors. Focus stays on `<body>`, `#routeStatus` is set to `""` so nothing is announced, and on `#a-*` and `#sport-*` the nav still marks "ענפים" as current.
   Fix: render `<h1 tabindex="-1">הדף לא נמצא</h1>` inside `notFound()`, and set `nav = ""` when a sub-view returns not-found.
2. **`#calendar-<unknown>` shows an empty calendar instead of not-found.** On `#calendar-nope` the select still shows "כל הענפים" while the list says "אין תחרויות שמתאימות לסינון".
   Fix: return `notFound()` when `sportFilter` is set but `!sportById(sportFilter)`.
3. **Calendar filter state is inconsistent.** The sport filter resets when you navigate to `#calendar`, but "רק העפלה" and "כולל שהסתיימו" persist in memory across routes.
   Fix: decide which behaviour is wanted and apply it to all three filters.
4. **The athlete stage track shows stage colour in the gaps.** `.track.s1` picks up the global `.s1{background:var(--blue)}` (and the same for s0/s2/s3), so the container is filled. The gaps between segments show blue or orange, which looks like tick marks on the grey part (computed `.track` background: `rgb(21,70,168)`). This happens in both light and dark.
   Fix: rename the modifier (for example `track st1`), or scope the bar colours to `.bar4 .s1`.
5. **`document.title` never changes per route.** Every page is titled "הדרך ללוס אנג׳לס 28", which affects history, tabs and screen-reader page announcements.
   Fix: set `document.title = h1 + " · הדרך ללוס אנג׳לס 28"` in `navigate()`.
6. **The search result count disagrees with the cards shown when there are more than 24 hits** (found by code inspection; the fixture never exceeded 17). `qCount` reports `hits.length`, but only 24 cards are rendered, with no "showing 24 of N" message.
7. **`body` keeps the browser's default 8px margin.** The sticky nav and page don't reach the screen edges, which is visible at the top and sides on both desktop and mobile.
   Fix: `body{margin:0}`.
8. **Data copy uses an apostrophe instead of a geresh in 63 strings** (`.athletes.event/rank/notes/name`, `.sports.window.summary`), against the CLAUDE.md rule.
   Fix: belongs to the daily job prompt (`job/SKILL.md`) or the export normalisation, not the front end.
9. **`index.html` has no charset declaration.** This is fine inside the artifact host, but local previews served with `http.server` show mojibake.
   Fix: add `<meta charset="utf-8">` at the top of `index.html` (harmless inside the host), or document how to serve locally.
10. **Same-year date ranges repeat the year and wrap awkwardly** in the 150px `.when` column, for example "29 באוק׳ 2026 – 31 באוק׳ / 2026".
    Fix: drop the year from the start date when it matches the end year.
11. **Hard-coded colours outside the tokens:** `.btn{color:#1c1204}` and `dialog::backdrop`. CLAUDE.md says colours come only from tokens. They were legible in dark mode, but should be tokenised.
12. **Search matches an athlete's sport only by its Hebrew name.** `judo` finds the sport chip but 0 athletes.
    Fix: add `sportById(a.sportId)?.en` to the haystack.
