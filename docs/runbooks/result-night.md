# Runbook: quota result night

For the owner and the team on a night when a competition can decide an LA28 quota for Israel.
Example used throughout: **artistic gymnastics, men's team final, Rotterdam, 2026-10-20**
(quota item `artistic-gymnastics` / `קבוצתי גברים`, top 3 teams earn a quota).

Roles: **owner** (edits quotas), **fact-checker** (Dana; signs off the item), **lead** (reviews and merges),
**editor** (anyone with edit rights on the page; approves the stage proposal), **Publisher** (Omer; takes it live).

This file covers steps 1–5, up to a signed-off PR. Merging, building, exporting, validating, publishing, the live
check, the digest text and rollback are all in [publishing.md](publishing.md).

Rules that don't bend on a result night:
- Nothing public states a quota without an official source. "earned" needs an IF/NOC/IOC allocation source, not a
  news story and not a provisional result list.
- Edit only `data/quotas/quotas.json` (the master). `site/quotas.json` is generated by `job/build_quotas.py`.
- `earned` in quotas.json must match an athlete at stage ≥ 2 in the published data.json. The validator enforces
  this, so the stage change goes live **before** the quota item (step 4 here comes before publishing.md step 4).
- The daily job never edits quotas. It only adds a "לעדכן quotas.json: …" warning to `runs/<date>` and, when the
  result clearly awards a quota, stage proposals.

## 1. Verify the official result (owner, same night)

1. Open the IF's official result for the session (for gymnastics: the FIG/competition results PDF of the team final).
2. Check the allocation rule in the item's `source` (the qualification system PDF), e.g. "3 הנבחרות המובילות בגמר
   הקבוצתי". Decide which of these applies:
   - **Quota clearly awarded** (Israel inside the allocation, result official): go on with `earned`.
   - **Provisional** (protest window, results "unofficial", reallocation pending): only update `israelNote`
     with the facts and an absolute date. Keep `in-contention`. Repeat this runbook when the IF confirms.
   - **Not awarded**: set `outside` or keep `in-contention` if a later route exists, and update `nextQuotaEvent`.
3. Save the official URLs you used: the result list and, for `earned`, the allocation or confirmation page.

## 2. Edit the master (owner)

```sh
cd ~/workspace/IL2LA28
git checkout main && git pull
git checkout -b dev/<you>/quotas-gymnastics-2026-10-20
date -u +%Y-%m-%dT%H:%M:%SZ        # use as the new top-level "updatedAt"
```

In `data/quotas/quotas.json`, edit only the affected item(s):

| Field | Set to |
|---|---|
| `israelStatus` | `earned` / `in-contention` / `outside` (step 1) |
| `israelNote` | Short Hebrew fact with an absolute date and geresh, e.g. `נבחרת הגברים במקום 3 בגמר הקבוצתי ברוטרדם (20.10.2026)` |
| `source` | The official https URL that proves the status (for `earned`: the allocation/result) |
| `nextQuotaEvent` | The next event that can change this item, or `null` (also for an item that becomes irrelevant, e.g. `outside` because the team qualified) |
| `earnedAt` | For `earned` only: the date of the deciding result, `YYYY-MM-DD`. Without it the home banner and the today-strip line don't appear. |
| `review` | `{"status": "unchecked", "by": "<you>", "at": "2026-10-20"}`. The build skips it until signed off; for `earned`, until Dana and Tamar sign off |

Also set the top-level `updatedAt` to the value printed by `date` above.

## 3. Fact-check (Dana; for `earned`, Dana and Tamar)

Dana compares the item with the sources and sets `review` to `{"status": "ok", "by": "dana", "at": "<date>"}`, or
`"fixed"` if she corrected it. She commits on the same branch.

**`earned` is approved by Dana and Tamar together, without the owner** (owner decision, 2026-10-18). The item stays
`unchecked` until both have checked it; then `review` is `{"status": "ok", "by": "dana+tamar", "at": "<date>"}`.


```sh
git add data/quotas/quotas.json
git commit -m "Sign off gymnastics team quota after Rotterdam final"
```

## 4. Stage change for the athletes (editor), only for `earned`

1. Open https://claude.ai/artifact/RyYBeRXq6pYwKdXujvTWvT signed in as an editor and go to the review queue.
2. If the job already created stage proposals (id `<athlete>-<YYYYMMDD>-stage`), check their evidence and approve
   them. If not, use the athlete edit form to set stage 2 with the official source in `source` and `notes`.
   For a team quota, this means the gymnasts in the official team-final line-up. The quota belongs to the NOC, so say
   that in the note.
3. Get it into the published data.json: [publishing.md](publishing.md) step 3 (run the daily task, fetch
   `/tmp/la28-data.json`, check the stage).

## 5. Build, validate and push (owner)

On the branch, run [publishing.md](publishing.md) steps 2 and 4: build `site/quotas.json` and run the validators
against `/tmp/la28-data.json`. `INVALID: … "earned" but no athlete … has stage >= 2` means step 4 here hasn't
reached the published data.json yet. Don't remove the check. Finish step 4 first. Then commit both files:

```sh
git add data/quotas/quotas.json site/quotas.json
git commit -m "Update gymnastics team quota after Rotterdam final" \
  -m "What: artistic-gymnastics/קבוצתי גברים -> earned. Why: official result <url>, allocation <url>. How tested: validator --quotas against published data.json, unit + smoke tests. Signed off: Dana."
git push -u origin dev/<you>/quotas-gymnastics-2026-10-20
```

The coordinator opens the GitHub PR. The lead reviews and merges with `git merge --no-ff`, and the Publisher takes
it from there: [publishing.md](publishing.md), from step 1.
